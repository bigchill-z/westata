fix(P8): exact robust VCE, correct rreg standard errors, complete e() scalars

A subagent audited my committed qreg/rreg against the fixture and found four
real defects. I re-verified each one independently before accepting it; all
four held.

1. rreg's standard errors were 26-36% wrong. The leave-one-out refit called a
   generic weighted least squares with an abs(u) <= scale threshold instead of
   the actual Huber-then-biweight estimator, so the pseudovalues were not
   pseudovalues of the estimator being reported.

     before  .0687508 / .0643232 / .0713078   (+26% / +14% / +36%)
     after   .0548424 / .0543542 / .0545657   (-2.8% / +3.4% / +0.1%)
       Stata .0564219 / .0525755 / .0545107

   The residual few-percent gap stays: [R] rreg cites Street-Carroll-Ruppert
   (1988) without specifying the leave-one-out construction, so it is documented
   rather than tuned.

2. qreg vce(robust) was approximate and is now exact. The sandwich needs an
   OBSERVATION-SPECIFIC density f_i = 2h / (x_i'(b(tau+h) - b(tau-h))), giving
   J = sum f_i x_i x_i' and V = J^-1 M J^-1 with no n/(n-k) correction.

     Stata  .0352211 / .0336117 / .0359358
     here   .0352211 / .0336117 / .0359358   (1e-6)

   Promoted from E2 to E3, and a conformance assertion was added so the claim is
   backed by a test rather than only by a registry edit.

3. Stata's documented e() scalars were missing: q_v, sparsity, f_r, bwidth,
   bwmethod, denmethod, convcode for qreg; mss, rss, r2, r2_a, F, rmse,
   huber_c, biweight_c for rreg.

4. e(q_v) used an interpolated quantile. Stata prints the ceil(n*tau)-th order
   statistic: at tau=.25, n*tau=150 and its raw-deviation centre is sorted[149].

Two items the agent flagged were already correct in my tree and needed no
change: there is no duplicate "qreg, vce(robust)" entry, and the conformance
docstring already carries .0514629 for the qreg 0.75 intercept SE.
