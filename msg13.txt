feat(etregress): implement method=ml, Stata default, with a likelihood derived and verified

`etregress ..., ml` raised UnsupportedError. It is now implemented: likelihood 1.6e-15, coefficients 1.8e-06,
standard errors 2.4e-03 against Stata. This is Stata DEFAULT for etregress -- `twostep` is the option -- so the
common invocation was the unsupported one.

THE LIKELIHOOD HAD TO BE DERIVED, because `_etregress_lf2` is a compiled built-in with no ado source (like
`_qreg`). Derivation, from the model `etregress.ado` documents at lines 652-669:

    y = x'b + d t + e            every row, d inside b since t is a regressor
    t* = z'g + u,  t = 1[t*>0]
    (e,u) bivariate normal; sigma = exp(lnsigma), rho = tanh(athrho)

    f(y,t) = f(y) P(t|y),   P(t=1|e) = Phi( (z'g + rho e/sigma)/sqrt(1-rho^2) )
                            P(t=0|e) = Phi(-(z'g + rho e/sigma)/sqrt(1-rho^2) )

    ll_i = -ln sigma - 1/2 ln(2 pi) - 1/2 (e_i/sigma)^2
           + ln Phi( (2 t_i - 1)(z_i'g + rho e_i/sigma)/sqrt(1-rho^2) )

VERIFIED at STAT ESTIMATES: -1124.6936827646718 against Stata -1124.693682764672, relative 2.0e-16.

WHY THIS IS NOT HECKMAN'S LIKELIHOOD, even though the parameterisation is identical: heckman applies the outcome
density only to selected rows and gives censored rows `ln Phi(-z'g)` alone; etregress keeps every row's outcome
density and multiplies by the conditional probability of the arm observed. Sharing an implementation would
silently fit a different model and still converge.

The `(2t-1)` factor is what lets one expression cover both arms: +1 treated, -1 untreated.

Optimisation is Nelder-Mead directly, with no quasi-Newton stage, for the reason the heckman ML work established
by measurement: a bounded L-BFGS-B pass in front moved the point where the polish could not recover, and
`athrho`'s tanh saturation makes that failure silent.

THE SEVENTH SWEEP-SCRIPT INSTANCE, and the last of its kind here: with this replaced, the aggregate now contains
ONE error row, `teffects nnmatch biasadj()`, which is compiled Mata and not reachable by reading. The capability
gaps went 8 -> 1 across these rounds, and every one of the seven removed was blocked by a script that assumed the
feature was absent.

Two mechanical notes, both costing a round-trip each:

    inside the target class fixed it;
  - a "already present" guard matched a CALL site rather than the DEFINITION, so a re-add script exited without
    adding anything. Checking for `def <name>(` rather than `<name>` is the difference.
