feat(discrete): implement fweight for logit/probit/poisson, by row expansion

The sweep recorded a capability gap rather than a numeric defect:

    TypeError: _DiscreteBase.fit() got an unexpected keyword argument 'weights'
    Stata accepted it and reports N=1207 (sum of weights)

It now fits, and the sweep grades it A: coefficients 2.53e-13, standard errors 8.47e-14.

STATSMODELS' freq_weights IS NOT THIS ESTIMATOR, which is the part worth recording. Two candidate
implementations, measured on identical data:

    sm.Logit(y, X, freq_weights=w).fit()   ->  [-0.11801,   0.02925]
    sm.Logit(y[idx], X[idx]).fit()         ->  [-0.152591,  0.021677]     idx = rows repeated by w

They disagree, and statsmodels also routes `freq_weights` through `_check_kwargs`, which warns "unknown kwargs
['freq_weights']" -- so it is not a supported path in this version either. Row expansion is both the faithful
reading of Stata's fweight ("each observation counts that many times") and the one that matches Stata, which is
what the sweep now confirms.

`e(N)` had to become the sum of the weights, not the row count. Stata reports 1205/1209 for weights summing to
that; a weighted fit labelled with the row count would read as correct and be wrong.

WEIGHT SUPPORT IS OPT-IN, and the models without it refuse. `_supports_freq_weights` defaults False; Logit,
Probit, Poisson and the ordered models set it True. `zip` and the other count models raise
ConsistencyError rather than fit unweighted -- because an unweighted estimate returned under a weighted call
reports valid-looking numbers for the wrong sample, with nothing to reveal it. A typo in the weight column name
and negative weights are errors for the same reason.

THE SWEEP SCRIPT HAD TO BE FIXED TOO, and this is the second time in two rounds. It called
`.fit(weights=df.w)` inside a `try` whose `except` recorded the gap, so after the fix it would have kept
recording a gap that no longer existed. A conformance script that hard-codes "not implemented" preserves the
claim indefinitely; it now compares. Same failure shape as the xtgls ar1 block last round, which suggests
these blocks should be reviewed for the pattern rather than fixed one at a time when they are noticed.

Sweep totals: A-tier 248 -> 249, error rows 7 -> 6. Suite: 1413 -> 1420 passing.
