## Linear models and IV

### `OLS`

**Stata:** `regress y x1 x2`

Ordinary least squares -- Stata's `regress`. Prints coefficients, standard errors, t statistics, p-values and confidence intervals, plus the ANOVA and fit blocks (`N`, `F`, `R²`, adjusted `R²`, root MSE). This is the reference implementation for the linear family: the small-sample correction, the `df_r` convention and the sum-of-squares block follow `[R] regress`, and the estimators that wrap a backend reuse those conventions rather than re-deriving them.

**Signature**

```python

```



### `FEOLS`

**Stata:** `reghdfe y x1 x2, absorb(firm year)`

Fixed-effects OLS with high-dimensional fixed effects -- Stata's `reghdfe`. The fixed-effect block is written after a `|` in the formula (`'y ~ x1 + x2 | firm + year'`), and absorption is PyFixest's alternating projections. `cov_type` accepts `nonrobust`, `HC0`, `HC1` and `cluster` only: `HC2`/`HC3` need the leverage of the full dummy design, which the backend does not expose for absorbed models, so they are refused rather than approximated.

### `PanelOLS`

**Stata:** `xtreg ypanel x1 x2, fe`

Fixed-effects panel regression -- Stata's `xtreg, fe`. `fit(entity_effects=True)` is the default. The formula implies a constant exactly as in `OLS`, so `e(b)` includes `Intercept` even though the within transformation absorbs it; write `'ypanel ~ x1 + x2 - 1'` to follow Stata's `noconstant`. Rows with missing values are dropped listwise before estimation, so `e(N)` can be smaller than `len(data)`, and the summary prints the `sigma_u`/`sigma_e`/`rho` block and the F test that all `u_i` are zero.

### `RandomEffects`

**Stata:** `xtreg ypanel x1 x2, re`

Random-effects GLS -- Stata's `xtreg, re`. ### `BetweenOLS`

### `FirstDifferenceOLS`

**Stata:** `xtreg ypanel x1 x2, fd`

First-difference estimator -- Stata's `xtreg, fd`. Every period is differenced against the immediately preceding one (`t` against `t - 1`, so a missing period is not bridged) and the model is fitted without a constant; the patsy intercept is therefore removed before the design reaches the backend, which rejects a constant in a first-difference regression. On a 40-entity, 5-period panel that leaves 160 usable observations, which is what `e(N)` reports.

### `IV2SLS`

**Stata:** `ivregress 2sls ytreat x1 (treat = x3)`

Two-stage least squares -- Stata's `ivregress 2sls`. The formula uses linearmodels' grammar, `'ytreat ~ x1 + [treat ~ x3]'`; Stata's `(endog = instrument)` spelling is rejected, because the grammar is delegated to the backend instead of reimplemented. Exogenous regressors, endogenous regressors and excluded instruments are named separately, and `e(b)` is reported in Stata's order -- endogenous first, included exogenous after, `_cons` last -- even though the design matrix is built the other way round.

### `IVLIML`

**Stata:** `ivregress liml ytreat x1 (treat = x3)`

Limited-information maximum likelihood -- Stata's `ivregress liml`. Solves the k-class problem with the LIML `kappa`, reported as `e(kappa)`. Under exact identification that `kappa` is 1 and the estimates equal 2SLS; when the model is over-identified it departs from 1 and the estimates differ. Both were measured on the fixture frame: exactly identified, `e(kappa)` prints 1.0 and the coefficients coincide with `IV2SLS`; adding a second instrument gives `kappa` about 1.0183 and visibly different coefficients.

### `IVGMM`

### `QuantileRegression`

**Stata:** `qreg y x1 x2, quantile(.5)`

Quantile regression -- Stata's `qreg`. Minimises the check function at `quantile`, solved by IRLS; because the objective is piecewise linear, several parameter vectors can attain the same minimum and the solver returns one of them. Standard errors use Stata's `fitted` sparsity estimator -- the regression is re-fitted at `quantile ± h` with the Hall-Sheather bandwidth -- not a kernel density of the residuals, which would move every standard error while leaving the coefficients alone. Two reporting details are easy to misread: `e(sum_adev)`/`e(sum_rdev)` are check-function sums rather than sums of absolute values, and `e(q_v)`, printed as "(about q)", is the `ceil(n*tau)`-th order statistic of the outcome, not an interpolated quantile.

### `Bsqreg`

### `Sqreg`

### `SurveyDesign`

A declared complex survey design -- the counterpart of `svyset`. ### `SvyRegress`

## Resampling

### `Bootstrap`

## Postestimation functions

### `testnl`

**Stata:** `testnl exp(_b[x1]) = 2`

Wald test of one or more nonlinear constraints (Stata `testnl`). The expression is parsed against a fixed whitelist -- `_b[name]`, the seven functions `exp`, `log`, `sqrt`, `sin`, `cos`, `logit`, `invlogit`, and arithmetic -- and is never handed to `eval`, so text such as `__import__('os')` fails validation instead of running. A bare expression is tested against zero; several constraints separated by commas or by whitespace (including Stata's grouped `(a = 0) (b = 0)`) are tested jointly. The statistic is chi2(q) with q the number of constraints, as `[R] testnl` reports it, and the command is reachable as `result.testnl(expr)` or `ws.testnl(result, expr)`.

**Signature**

```python
ws.testnl(result: 'Any', expression: 'str') -> 'WaldTest'
```

**Example**

```python
ws.testnl(ws.Logit.from_formula('yb ~ x1 + x2', base).fit(), 'exp(_b[x1]) = 2')
```

**Output**

```text
  ( 1) exp(_b[x1]) = 2

chi2(1) =       1.36
Prob > chi2     =     0.2437
```

**Notes:** The derivatives entering the variance are central differences with the step `1e-6 * max(1, |b_j|)`. A linear constraint therefore reproduces `lincom` exactly; only genuinely nonlinear functions are approximated.

### `lrtest`

**Stata:** `lrtest unrestricted restricted`

Likelihood-ratio test of a nested pair (Stata `lrtest`): `LR = 2(ll_unrestricted - ll_restricted)`, referred to chi2 with the difference in parameter counts. Both fits must be on the same sample, and equal parameter counts raise `ConsistencyError` -- Stata's `r(498)` -- because chi2(0) is a point mass and reporting `p = 1` would turn a Stata error into a successful command. A pair whose counts differ but which is not nested still gets a statistic; it is usually negative, and that is reported with a warning rather than clamped. Callable as `ws.lrtest(unrestricted, restricted)` or `unrestricted.lrtest(restricted)`.

**Signature**

```python
ws.lrtest(unrestricted: 'Any', restricted: 'Any') -> 'LRTestResult'
```

**Example**

```python
full = ws.Logit.from_formula('yb ~ x1 + x2 + x3', base).fit()
full.lrtest(ws.Logit.from_formula('yb ~ x1 + x2', base).fit())
```

**Output**

```text
Likelihood-ratio test
  LR chi2(1) = 6.72
  Prob > chi2     = 0.0095
```

**Notes:** Nesting is decided from the parameter COUNTS alone, exactly as Stata decides it. A coefficient-name mismatch is reported as a warning rather than a refusal, because Stata computes the statistic anyway.

### `hausman`

**Stata:** `hausman fe re`

Hausman specification test of an efficient estimator's consistency (Stata `hausman`). The consistent-but-inefficient fit (e.g. `xtreg, fe`) comes first and the efficient one (e.g. `xtreg, re`) second, and the statistic is `(b_c - b_e)'[V_c - V_e]^-1(b_c - b_e)` over the shared coefficients. The constant is excluded unless `constant=True`, because a within-transformed intercept and a GLS intercept estimate different population quantities; `constant=True` is Stata's `hausman ..., constant`. Callable as `ws.hausman(consistent, efficient)` or `consistent.hausman(efficient, constant=True)`.

**Signature**

```python
ws.hausman(consistent: 'Any', efficient: 'Any', *, constant: 'bool' = False) -> 'HausmanResult'
```

**Example**

```python

re = ws.RandomEffects.from_formula('ypanel ~ x1 + x2', base, entity='firm', time='year').fit()
ws.hausman(fe, re)
```

**Output**

```text
Hausman test
  chi2(2) = 1.60
  Prob > chi2 = 0.4501
```

**Notes:** When `V_c - V_e` is not positive definite the matrix is inverted with a pseudo-inverse and the statistic is floored at 0, whereas Stata prints the negative value it computes. `df`, `p` and the warning still agree; only the sign of an uninterpretable statistic differs, because a pseudo-inverse routinely yields about `-1e-18` through round-off.

### `nlcom`

**Stata:** `nlcom exp(_b[x1])`

### `estat_weakrobust`

**Stata:** `estat weakrobust`

Weak-instrument-robust inference (Stata `estat weakrobust`): it reports the Anderson-Rubin test, whose distribution does not depend on instrument strength. That is Stata's default for a just-identified model; for an overidentified one Stata's default is Moreira's conditional likelihood-ratio test, and since CLR needs a simulated conditional distribution that is not implemented here, an overidentified fit must pass `ar=True` or the call raises `NotImplementedError` with that reason. `betanull` sets the null on the endogenous coefficients: a mapping, a positional sequence, or `None` for all zero. Use `result.estat_weakrobust()` or `westata.postestimation.weakrobust.estat_weakrobust(result, ar=True)`; it is not re-exported into `ws`.

**Signature**

```python
ws.estat_weakrobust(self, **kwargs: 'Any') -> 'Any'
```

**Example**

```python
ws.IV2SLS.from_formula('y ~ x1 + [x2 ~ x3]', base).fit().estat_weakrobust()
```

**Output**

```text

Weak-instrument-robust inference
Anderson-Rubin chi2(1) =    1.7538
               F(1,197) =    1.7538   Prob > F = 0.1869
```

**Notes:** `betanull` as a sequence is assigned BY POSITION, which is Stata's `copy` suboption; a sequence of the wrong length is refused rather than padded or truncated, because either would test a different hypothesis than the caller wrote.

### `linktest`

**Stata:** `linktest`

Pregibon's link test for a specification error (Stata `linktest`). The model is REFIT with `_hat` (the fitted linear index) and `_hatsq` in place of the original regressors, and the reported t is `b[_hatsq]/se[_hatsq]` with the REFIT's residual degrees of freedom (`linktest.ado:131-132`). Because that refit always has three parameters -- `_hat`, `_hatsq` and the constant -- the df is n-3 whatever the original model was, so it is not simply the original fit's `df_r`. A significant squared term says the linear index is mis-specified: the functional form is wrong, not merely the fit. `xt*`, `iv*`, `sureg`, `mvreg`, `eivreg`, `zip` and `zinb` are refused because their linear index is not a single `xb`. Available as `result.linktest()`.

**Signature**

```python
ws.linktest(self) -> 'Any'
```

**Example**

```python
ws.OLS.from_formula('y ~ x1 + x2', base).fit().linktest()
```

**Output**

```text

Pregibon's link test
H0: the link is specified correctly

  _hat        =  1.092729
  _hatsq      = -0.041148
  t           =   -0.7700
  P>|t|       =    0.4422   (df = 197)
```

**Notes:** The standalone function is `westata.postestimation.linktest.linktest(result)` -- not `ws.linktest`; it needs the estimation-sample data and the response name, which are only retained by the formula interfaces.

### `suest`

**Stata:** `suest model1 model2`

Stack several fits into one parameter vector and one simultaneous sandwich covariance (Stata `suest`). The cross-model block is NOT zero: the stacked score of each observation puts the two models' contributions together, which is exactly what keeps the covariance valid when the models share observations. `cluster=` sums each observation's stacked score within its cluster before the outer product. The models must have the same sample size, and a model that cannot produce scores -- a non-linear estimator whose score is not the residual, or one with no design matrix -- raises `NotImplementedError`. Reachable as `result.suest(other, ...)` -- note that `suest` is a METHOD here, not a top-level `ws.suest`; the module function is `westata.postestimation.suest.suest((model1, model2), cluster=...)`, which takes the fits as one sequence.

**Signature**

```python
ws.suest(self, *others: 'Any', **kwargs: 'Any') -> 'Any'
```

**Example**

```python
a = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
a.suest(ws.OLS.from_formula('y1 ~ x1 + x2', base).fit())
```

**Output**

```text

Simultaneous covariance matrix
  2 models, 6 parameters, 200 observations
  parameters: model1:Intercept, model1:x1, model1:x2, model2:Intercept, model2:x1, model2:x2
```

**Notes:** Estimate the components WITHOUT `vce(robust)`/`vce(cluster)`, as `suest.sthlp` advises: `suest` supplies the robust covariance itself, so a robust component would be doubly corrected.

### `newey`


**Example**

```python
ws.newey('y ~ x1 + x2', base, lag=2, time=np.arange(1.0, 201.0)).summary(style='stata')
```

**Output**

```text

Maximum lag = 2

---------+----------------------------------------------------------------------
x1       |     .8406445    .06629431    12.68    0.000     .7099069     .9713822
```

### `unitroot`

**Stata:** `dfuller y, lags(2)`

Unit-root test, selected by `test`: `'adf'` for Stata's `dfuller`, `'pp'` for `pperron` and `'kpss'`. `regression` picks the deterministic terms (`'c'`, `'n'`, `'ct'`, `'ctt'`) and `autolag` selects the lag length the statsmodels way, while `None` uses `maxlag` verbatim as Stata's `lags(#)` does. **Example**

```python
ws.unitroot(base['y'], test='adf', regression='c', maxlag=2)
```

```text
  statistic = -6.70616   p-value = 0.0000
  lags = 2   obs = 197
  critical: 1%: -3.478  5%: -2.884  10%: -2.574

```

**Notes:** The p-value is unaffected by the critical-value convention and remains the MacKinnon one; only the printed band comes from Stata's table.

### `normalize_weights`

**Stata:** `[fw=], [aw=], [pw=], [iw=] -- the weight normalization rules of [U] 20.24`

Normalizes a weight array according to Stata's rule for the given type and returns a `WeightSpec`. The four types differ in a way that changes the numbers: `fweight` and `iweight` are left unnormalized and contribute `sum(w)` as the effective sample size, while `aweight` and `pweight` are rescaled to sum to the row count and contribute `N`; `pweight` additionally sets `implies_robust`, which is the only difference between it and `aweight`. **Signature**

```python
ws.normalize_weights(weights: 'Any', weight_type: 'str') -> 'WeightSpec'
```

**Example**

```python

(s.effective_n, s.implies_robust, s.n_obs)
```

**Output**

```text
(10.0, False, 4)
```

**Notes:** `effective_n` is what the degrees of freedom use: 10 for this four-row `fweight` example, because each row counts as its weight. That is why `nobs` and `e(N)` diverge under frequency weights.


## Working with a fitted result

### `StataResults`

**Stata:** `(the object every estimation command returns, analogous to Stata's e() results)`

The object returned by every `fit()`. It carries a statsmodels-compatible surface (`params`, `bse`, `pvalues`, `conf_int`, `cov_params`), the Stata `e()` macros as a dictionary, and the postestimation commands as methods -- `test`, `lincom`, `margins`, `predict`, and the twenty `estat_*` forwarders. This is where most day-to-day work happens after a fit.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.e['r2']
```

**Output**

```text
0.4802098236178376
```

**Notes:** The `e()` key set differs per command; it is not uniform, and assuming otherwise is how invented keys get added. `e(ic)`, `e(aic)` and `e(title)` are each present for some commands and absent for others.

### `params`

**Stata:** `regress -- the `Coef.` column, i.e. `e(b)``

Point estimates as a `pandas.Series` indexed by `param_names`, in the column order the design matrix was built with. That order is patsy's, which puts the constant FIRST (`Intercept`), whereas Stata's `e(b)` puts `_cons` LAST; the two vectors hold the same numbers in a different order. Use `stata_params` when the comparison is against Stata's `e(b)`.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.params
```

**Output**

```text
Intercept    1.005003
x1           0.840645
x2          -0.512087
Name: params, dtype: float64
```

### `bse`

**Stata:** `regress -- the `Std. err.` column`

Standard errors, the square roots of the diagonal of the covariance matrix that `cov_type` selected. They are computed once at construction from `cov`, so a caller who changes the covariance afterwards does not change `bse`.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.bse
```

**Output**

```text
Intercept    0.074428
x1           0.072471
x2           0.074822
Name: bse, dtype: float64
```

### `pvalues`

**Stata:** `regress -- the `P>|t|` column; logit -- the `P>|z|` column`

Two-sided p-values for the null that each coefficient is zero. The reference distribution follows `dist`: Student t with `df_resid` degrees of freedom when `dist` is `"t"`, the standard normal when it is `"z"`. A model whose `df_resid` is `G - 1` from a clustered VCE therefore uses that count, not `nobs - k`.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.pvalues
```

**Output**

```text
Intercept    7.633899e-30
x1           4.755835e-24
x2           9.518706e-11
Name: pvalues, dtype: float64
```

### `tvalues`

**Stata:** `regress -- the `t` column`

The coefficient divided by its standard error, always named `tvalues` even for a z-based model. It is the test statistic, not a t statistic as such: for a logit fit the same numbers are the z statistics Stata prints. `zvalues` is the same object under the name the distribution calls for.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.tvalues
```

**Output**

```text
Intercept    13.502927
x1           11.599724
x2           -6.844043
Name: tvalues, dtype: float64
```

### `zvalues`

**Stata:** `logit, probit, poisson -- the `z` column`

The normal statistic for the null that a coefficient is zero. It is numerically identical to `tvalues` -- both are `params / bse` -- and is exposed under this name so downstream code can branch on the inference distribution without recomputing it. It is an alias, not an independent calculation, so the Series it returns still carries the name `tvalues`.

**Example**

```python
r = ws.Logit.from_formula('yb ~ x1 + x2', base).fit()
r.zvalues
```

**Output**

```text
Intercept    1.032644
x1           3.466025
x2          -0.888860
Name: tvalues, dtype: float64
```

### `fvalue`

**Stata:** `regress -- the `F(k, n-k)` model test`

The model's joint F statistic, read from `e(F)`; NaN when the command does not store it. Likelihood-based commands report a chi-square model test instead, stored as `e(chi2)`, so `fvalue` is NaN after a logit or Poisson fit -- that is the correct absence, not a missing calculation.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.fvalue
```

**Output**

```text
90.99954130641446
```

### `llf`

**Stata:** `e(ll) -- the log-likelihood`

The maximised log-likelihood, read from `e(ll)`; NaN when the command does not record it. It is the number `estat ic` and `lrtest` build their statistics from, so a fit that reports NaN here cannot support either of them.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.llf
```

**Output**

```text
-291.7997221200006
```

### `aic`

**Stata:** `e(aic) -- note that `estat ic` is the surface that matches Stata's printed table`

AIC read from `e(aic)`; NaN when the command does not record it. For `regress` this is NOT the number `estat ic` prints: `regress` stores no AIC at all, and the value exposed here is on the Gaussian-deviance scale, `N log(rss/N) + 2k`, which is a different quantity from the likelihood-scale `-2 logL + 2k`. For commands that do store `e(aic)` the two agree.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
(r.aic, ws.estat_ic(r).aic)
```

**Output**

```text
(22.024030958132094, 589.5994442400012)
```

**Notes:** Do not compare `result.aic` against `estat ic` output for a `regress` fit; they are on different scales. `e(_aic_is_stata)` records which sense applies, and the summary table prints AIC only when that flag says the value is Stata's.

### `bic`

**Stata:** `e(bic) -- with the same caveat as `aic``

BIC read from `e(bic)`; NaN when the command does not record it. The same scale caveat as `aic` applies: after `regress` the stored value is the Gaussian-deviance `N log(rss/N) + k log(N)`, not the likelihood-scale criterion `estat ic` prints.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
(r.bic, ws.estat_ic(r).bic)
```

**Output**

```text
(31.918983057776202, 599.4943963396453)
```

### `nobs`

**Stata:** `e(N) / the `Number of obs` line`

The number of ROWS in the estimation sample, as an integer. It is deliberately not `e(N)` under frequency weights: with `fweight` the rows are replication counts, so `e(N)` becomes `sum(w)` while `nobs` stays the row count. Use `result.e['N']` for the effective sample size.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
(r.nobs, r.e['N'])
```

**Output**

```text
(200, 200.0)
```

### `df_model`

**Stata:** `e(df_m) -- model degrees of freedom`

Model degrees of freedom, i.e. the number of restrictions the model test imposes: the regressors excluding the constant. It is read from `e(df_m)`, so for a one-regressor model it is 1, not 2, even though the coefficient vector has two entries.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.df_model
```

**Output**

```text
2.0
```

### `df_resid`

**Stata:** `e(df_r) -- residual degrees of freedom`

The denominator degrees of freedom the reference distribution uses. It is NOT always `nobs - k`: for a clustered VCE it is `G - 1`, the number of clusters minus one. This property returns the value the estimator computed at fit time; `e(df_r)` is a separate matter, because that macro is only present for non-z models (or when an estimator such as `tobit` or `xtivreg` supplied it explicitly), so a logit fit has a `df_resid` here and no `e(df_r)`.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1', base).fit(cov_type='cluster', cov_kwds={'groups': base['firm']})
(r.df_resid, r.cov_type)
```

**Output**

```text
(39.0, 'cluster')
```

### `dist`

**Stata:** `(no Stata equivalent -- Stata picks t or z per command and stores it in e() indirectly)`

Which reference distribution inference uses: `"t"` for t statistics and t confidence intervals, `"z"` for normal tests. It is decided by the estimator, not by the caller, and it is what `pvalues` and `conf_int` branch on. A linear fit reports `t`; logit, probit and the count models report `z`.

**Example**

```python
r = ws.Logit.from_formula('yb ~ x1 + x2', base).fit()
r.dist
```

**Output**

```text
z
```

When the estimator did not record `e(cmd)`, this value is used to synthesise it, so `result.e['cmd']` is always available even though Stata always stores it.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
```

**Example**

The coefficient covariance matrix as a `k x k` numpy array, already carrying every small-sample correction that was requested. ### `e`

**Stata:** `e() -- the stored estimation results`

The Stata `e()` macros as a dictionary-like object with BOTH item and attribute access. Item access keeps normal mapping semantics and raises `KeyError` for a macro the command did not store; attribute access is deliberately forgiving and returns `None` instead. The key set DIFFERS PER COMMAND -- assuming uniformity is exactly how invented keys get added to a manual: `regress` stores no `aic` on the `estat ic` scale and `tobit` stores no `aic` at all.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()

```

**Output**

```text
['F', 'N', '_aic_is_stata', 'aic', 'bic', 'cmd', 'depvar', 'df_m', 'df_r', 'estat_cmd', 'll', 'll_0', 'marginsok', 'mss', 'properties', 'r2', 'r2_a', 'rank', 'rmse', 'rss', 'sigma', 'sum_w', 'title', 'vce', 'vcetype']
```

**Notes:** Two macros are synthesised because every command documents them: `e(depvar)` from the response name and `e(cmd)` from `model_name`. `e(cmdline)` is deliberately NOT synthesised -- it records the command as typed, options included, and this package has no such string, so inventing one would fabricate a value.

### `fittedvalues`

**Stata:** `predict, xb -- the linear prediction`

The fitted values on the estimation sample, a numpy array of length `nobs` in row order. For weighted fits these are the predictions of the weighted least-squares problem, not weighted fitted values. `predict(kind='xb')` recomputes the same quantity from the retained design matrix, which is what to use for out-of-sample data.

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.fittedvalues[:5]
```

**Output**

```text
[2.524914 0.144945 1.126616 2.107762 0.869349]
```

### `resid`

**Stata:** `predict, residuals -- the residuals`

Residuals on the estimation sample, `y - fittedvalues`, a numpy array of length `nobs`. They are raw residuals, not standardised or studentised ones, and for weighted fits they are the raw deviations rather than the weighted residuals.

**Example**

### `rsquared`

**Stata:** `e(r2)`

R-squared read from `e(r2)`; NaN when the command does not record it. This exists for the OLS family; the maximum-likelihood families store a pseudo R-squared in `e(r2_p)` instead and leave this NaN, so a NaN here means "this model has no R-squared", not a failed computation. Read `e['r2_p']` for logit, probit and the count models.

**Example**

```python

((ols.rsquared, lg.rsquared), lg.e['r2_p'])
```

**Output**


The estimation-sample data frame the fit was computed on. Stata exposes the same information through e(sample) and the saved dataset; here it is the frame itself, which is why postestimation commands that must re-read the estimation data -- linktest, estat_mundlak, predict with an explicit sample -- can work from a fitted result without the caller passing the data again.

### `converged`

**Stata:** `e(converged) -- 1 if the optimizer converged`

**Example**

### `test`

**Stata:** `test x1 = 0`

Wald test of linear hypotheses (Stata `test`). A bare coefficient list (`'x1 x2'`) tests that EACH is zero -- a joint test, not a test of their sum -- and `*` expands as a wildcard; `'x1 = x2'` and the chain `'x1 = x2 = x3'` test the corresponding equalities; several constraints are separated by commas inside one string or passed as separate arguments. `coef=True` additionally returns a dict with Stata's constrained estimates `b_c = b - VR'(RVR')^-1(Rb - r)`, their covariance, and the test itself. The statistic is F when the model reports t and chi2 when it reports z, on `df_resid` -- for a clustered VCE that is `G - 1`, not `nobs - k`. Available as `result.test(...)`.

**Signature**

```python
ws.test(self, *specs: 'Any', **kwargs: 'Any') -> 'Any'
```

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.test('x1 = 0')
```

**Output**

```text
  ( 1) x1 = 0

F(1, 197) =     134.55
Prob > F        =     0.0000
```

**Notes:** A constant inside a bare coefficient list is an error, not a hypothesis: Stata answers it with `r(111) '<n>' not found`, so put it on the right-hand side of `=` (`'x1 = 0'`), where it is accepted.

### `lincom`

**Stata:** `lincom x1 - x2`

One linear combination of the coefficients (Stata `lincom`): `L b` with standard error `sqrt(L V L')` and the model's own reference distribution. A bare constant is moved to the right-hand side of the printed constraint and never enters the variance, so `lincom('2*x1 - x2 + 3')` has exactly the same standard error as `lincom('2*x1 - x2')`. An `=` sign or a comma is rejected -- Stata's syntax is ONE expression, and a comma separates the expression from its options -- so several combinations belong in `test`. `eform=True` reports `exp(Lb)` with an exponentiated interval. Returns a LincomResult whose `to_dict()` gives Stata's `r()` names.

**Signature**

```python
ws.lincom(self, expression: 'str', **kwargs: 'Any') -> 'Any'
```

**Example**

```python
r = ws.OLS.from_formula('y ~ x1 + x2', base).fit()
r.lincom('x1 - x2')
```

**Output**

```text
x1 - x2 = 0
                   Coef.   Std. err.       t   P>|t|        [95% conf. interval]
                1.352732   0.1039679   13.01   0.000      1.147699      1.557764
```

**Notes:** For a z-based fit the statistic is stored as `r(z)` and `r(df)` is genuinely absent -- asking for the other name finds nothing, which matches Stata rather than coercing a value into existence.

### `predict`

**Stata:** `predict yhat, pr`

**Signature**

## Errors and support types

### `WestataError`

**Stata:** `(no Stata equivalent -- an exception base class)`

The base class of every westata-specific failure. Catching it handles the whole family at once: `ConsistencyError`, `ConvergenceError`, `WeightError`, `FormulaError` and `UnsupportedError` all subclass it, so a caller who only wants to separate westata's own refusals from numpy or pandas errors can catch this one name. It does not catch `ValueError` raised for plain bad arguments -- but two of its subclasses, `ConsistencyError` and `FormulaError`, are themselves `ValueError`s, so `except WestataError` does catch every VCE and formula refusal even though generic type errors still escape it.

**Example**

```python
[c.__name__ for c in (ws.ConsistencyError, ws.ConvergenceError, ws.WeightError, ws.FormulaError, ws.UnsupportedError) if issubclass(c, ws.WestataError)]
```

**Output**

```text
['ConsistencyError', 'ConvergenceError', 'WeightError', 'FormulaError', 'UnsupportedError']
```

### `ConsistencyError`

**Stata:** `(no Stata equivalent -- Stata refuses with return codes such as r(498) or r(2000))`

Raised when a result could not be guaranteed Stata-conformant, so the package refuses instead of returning a number it knows may diverge. This is the deliberate-failure channel: a clustered VCE with fewer than two clusters, an unidentified IV model, an `lrtest` between two models with the same parameter count, a `pweight` fit with a nonrobust covariance. The message states what diverged, so the refusal is auditable rather than mysterious. It is ALSO a `ValueError`, deliberately, so `except ValueError` continues to catch it while `except WestataError` now catches the VCE refusals too -- those two bases are what let one user error carry one exception type across OLS, logit and the IV estimators instead of two.

**Example**

```python
msg = None
try:
    r = ws.OLS.from_formula('y ~ x1', base).fit(cov_type='cluster', cov_kwds={'groups': np.zeros(len(base), dtype=int)})
except ws.WestataError as exc:
    msg = (type(exc).__name__, isinstance(exc, ValueError))
msg
```

**Output**

```text
('ConsistencyError', True)
```

**Notes:** `cov_kwds` key names are NOT uniform: OLS and the ML estimators take `{'groups': labels}`, while the IV estimators take `{'clusters': labels}` and reject `groups` as an unexpected entry. Pass the key the estimator documents, or the error you get will be about the kwds name rather than about your clusters.

### `ConvergenceError`

**Stata:** `(no Stata equivalent -- Stata reports `convergence not achieved` and returns estimates, r(430))`

Raised when an iterative estimator does not converge and the caller asked for a hard failure via `strict=True`. The default is `strict=False`, which returns the estimates anyway and records `converged=False`, matching Stata's behaviour of reporting non-convergence and keeping the estimates. Pass `strict=True` when an unconverged estimate is worse than no estimate.

**Example**

```python
msg = None
try:
    ws.Logit.from_formula('yb ~ x1 + x2', base).fit(maxiter=1, strict=True)
except ws.ConvergenceError as exc:
    msg = str(exc)
msg
```

**Output**

```text
logit: optimiser did not converge after 1 iterations; estimates may be unreliable
```

### `FormulaError`

**Stata:** `(no Stata equivalent -- Stata raises r(111) for an unknown variable)`

Raised when a model formula cannot be evaluated on the given data: an unknown column, a malformed term, a factor that does not exist. It wraps patsy's own error as a plain exception rather than letting `PatsyError` escape, because patsy keeps a namespace object in the traceback frame and several formatters -- pytest's included -- fail while introspecting it, hiding the real message. Like `ConsistencyError` it subclasses `ValueError` as well as `WestataError`, so generic argument-error handling still catches it.

**Example**

```python
msg = None
try:
    ws.OLS.from_formula('y ~ nosuchcolumn', base)
except ws.FormulaError as exc:
    msg = str(exc).splitlines()[0]
msg
```

**Output**

```text
cannot evaluate formula 'y ~ nosuchcolumn': Error evaluating factor: NameError: name 'nosuchcolumn' is not defined
```

### `UnsupportedError`

**Stata:** `(no Stata equivalent -- this means Stata CAN do it and westata cannot yet)`

Raised when a capability exists in Stata but is not implemented here -- the distinction from `ConsistencyError` matters. It also subclasses `NotImplementedError`, so an unknown predict type or an `estat` subcommand Stata supports but this package does not reaches the caller as an explicit gap rather than as a silently wrong number. The message names what was asked for and what IS available.

**Example**

```python
msg = None
try:
    ws.Logit.from_formula('yb ~ x1', base).fit().predict(kind='zzz')
except ws.UnsupportedError as exc:
    msg = str(exc)
msg
```

**Output**

```text
predict: 'logit' supports ('xb', 'stdp', 'pr', 'residuals', 'score'); got 'zzz'
```

### `WeightError`

**Stata:** `(no Stata equivalent -- Stata raises r(402) or r(401) for a bad weight)`

Raised for a missing, unsupported or ambiguous Stata weight specification: an unknown weight type, negative weights, missing weights, weights that sum to zero, or `weights` supplied without a `weight_type` (and vice versa). Weights are validated once, when the model is built, so the error names the offending condition rather than surfacing later as a NaN in the covariance.

**Example**

```python
msg = None
try:
    ws.normalize_weights(np.array([1.0, -1.0]), 'aweight')
except ws.WeightError as exc:
    msg = str(exc)
msg
```

**Output**

```text
weights must be non-negative
```

### `ExpListError`

**Stata:** `(no Stata equivalent -- Stata's exp_list parser reports r(198))`

Raised when text does not conform to Stata's `exp_list` grammar, or when a statistic names a stored result that does not exist. It subclasses `ValueError`. The two failure modes are kept apart in the message: a syntax error quotes the offending text and offset, while an unresolvable statistic lists the keys actually available, which is what makes `r(mean)` after a command that stores only `r(N)` diagnosable.

**Example**

```python
msg = None
try:
    ws.parse_exp_list('(((')
except ws.ExpListError as exc:
    msg = str(exc)
msg
```

**Output**

```text
unbalanced parentheses in '((('
```

### `PackageNotFoundError`

**Stata:** `(no Stata equivalent -- an importlib.metadata exception, re-exported)`

The `importlib.metadata` exception raised when a distribution's metadata cannot be found. It is re-exported so callers can catch it without importing `importlib.metadata` themselves, and it is what `westata.__version__` falls back from: running the source tree without installing leaves no distribution metadata, and the version then becomes the literal fallback rather than raising. It is NOT a `WestataError` -- it is an `ImportError` subclass from the standard library.

**Example**

```python
(ws.PackageNotFoundError.__module__, issubclass(ws.PackageNotFoundError, ImportError))
```

**Output**

```text
('importlib.metadata', True)
```

**Notes:** Because it is `importlib.metadata`'s class and not a westata error, `except ws.WestataError` does NOT catch it. Catch `ws.PackageNotFoundError` or `ImportError` directly.

### `StoredResults`

**Stata:** `r(), e(), _b[] and _se[] -- the four tables a replicate leaves behind`

The stored results of ONE replicate's command, as a frozen dataclass with four mapping fields: `r` and `e` hold scalars, `b` and `se` hold coefficients by name. These are exactly the four tables Stata's `exp_list` can reach, which is why a bootstrap or permutation statistic is written against this object. `lookup(table, key)` returns a float and raises `ExpListError` naming the available keys when the entry is absent.

**Signature**

```python

```

**Example**


**Output**

```text
{'n': 200.0, 'm': 1.5}
```

### `WeightSpec`

**Stata:** `[fw=], [aw=], [pw=], [iw=] -- the parsed weight specification`

The normalized weights plus the metadata the estimators need, produced by `normalize_weights` from a weight array and a Stata weight type. Fields: `weights` (already normalized per that type's rule), `weight_type`, `effective_n` (the sample size used for degrees of freedom), `implies_robust` (true for `pweight`, because Stata's `[pw=w]` implies `vce(robust)`), and `n_obs` (the row count, not the effective size). A frozen dataclass, so an estimator cannot quietly rewrite the specification after validation.

**Signature**

```python
ws.WeightSpec(weights: 'np.ndarray', weight_type: 'str', effective_n: 'float', implies_robust: 'bool', n_obs: 'int') -> None
```

**Example**


**Output**

```text

```

### `WEIGHT_TYPES`

**Stata:** `[fw=], [aw=], [pw=], [iw=]`

The four Stata weight type names accepted everywhere a weight is accepted, as a tuple: `fweight`, `aweight`, `pweight`, `iweight`. The meanings are the ones in `[U] 20.24`: frequency (integer replication counts, the sample is effectively `sum(w)`), analytic or precision (rescaled to sum to `N`, used like a frequency weight for the estimate), sampling (point estimate as with `aweight`, but the variance MUST be a linearized sandwich -- `[pw=w]` implies `vce(robust)`), and importance (used like a frequency weight without normalization). The part readers get wrong is that `fweight` and `aweight` give the same point estimate and differ only in the degrees of freedom, while `pweight` is the one that changes the VARIANCE.

**Example**

```python
ws.WEIGHT_TYPES
```

**Output**

```text
('fweight', 'aweight', 'pweight', 'iweight')
```

### `HausmanResult`

**Stata:** `hausman fe re`

The Hausman specification test: `(b_c - b_e)' [V_c - V_e]^-1 (b_c - b_e)`. Fields: `statistic`, `df` (the number of coefficients actually compared, constants excluded), `pvalue` (`P > chi2(df)`), and `excluded` (parameters not present in both models, so not comparable -- a diagnostic this package adds, not an `r()` scalar). A rejection means the efficient estimator is inconsistent, so the consistent one is preferred.

**Signature**

```python
ws.HausmanResult(statistic: 'float', df: 'float', pvalue: 'float', excluded: 'list[str]' = <factory>) -> None
```

**Example**

```python

```

**Output**

```text
Hausman test
  chi2(1) = 1.45
  Prob > chi2 = 0.2280
```

**Notes:** The difference matrix `V_c - V_e` can be singular or have negative eigenvalues in finite samples; the test compares only the coefficients present in both models, which is what `df` counts.
