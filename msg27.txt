docs: add Chinese README and guide, generated from the same measured data

Adds README.zh-CN.md (232 lines) and docs/GUIDE.zh-CN.md (577 lines), both translated AND verified --
translation alone would have produced an unverified copy of documents that were themselves only trusted
because they execute.

THE RULE THAT SHAPED THIS

Every number in the Chinese documents is READ from the same source as the English ones, never typed:

    registry counts      tests/conformance/registry.yml
    comparison figures   docs/comparison.json
    tables               rendered from that JSON by docs/gen_guide_zh.py

Two hand-maintained copies of the same statistic diverge; that is the failure mode the guide itself
warns about. So docs/gen_readme_zh.py and docs/gen_guide_zh.py generate, and the numbers are
interpolation rather than prose.

WHAT IS VERIFIED (tests/test_docs_zh.py, 7 tests)

    * every python block in both Chinese documents executes
    * the main comparison table's FIRST FOUR COLUMNS are byte-identical to the English table
    * the parameter-detail row count equals the JSON's parameter total
    * the section count matches the English README (translation, not abridgement)
    * all nine E1 commands appear

The fourth check exists because a translated document can quietly become a shorter one. The second
exists because a translated document can quietly become a differently-numbered one. Neither is visible
by reading.

WHAT THE TRANSLATION DOES NOT DO

Command names, parameter names and numbers are NOT translated -- `C(foreign)[T.1]` stays
`C(foreign)[T.1]`, and `3.6e-16` stays `3.6e-16`. Translating identifiers would create ambiguity where
the whole point is exactness. Only the prose and the verdict column ("machine precision" ->
"机器精度") differ, which is why the test compares four columns rather than five.

FOUR ASSERTION ERRORS FOUND AND FIXED WHILE WRITING THE TESTS, each instructive

1. A regex for parameter-detail rows also matched the main comparison table, because that table's first
   column is also a backticked name. Counted 99 and then 108 instead of 71. Fixed by locating tables
   through their HEADER rather than by row shape -- the same row shape means different things in
   different tables, so shape-based identification is wrong and context-based is right.

2. Comparing the main tables line-for-line reported every row as different, because the last column
   legitimately differs in language. Fixed by comparing the four numeric columns, which is what must
   agree; relaxing to "similar" would have been the wrong direction.

3. A triple-quoted string nested inside a triple-quoted PowerShell here-string produced a file that
   pytest still reported as "4 passed", because the file was never modified. The same
   looks-like-it-worked-and-did-nothing pattern has now appeared four times in this project (MANIFEST.in
   BOM, the generator's leaked string literals, this, and the escaped newline below). Scripts that edit
   files now assert the file grew.

4. An escaped `\n` inside a written string was written as a real newline, splitting an assertion across
   lines. Caught by ast.parse rather than by running the test, which is the cheaper order.
