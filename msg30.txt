release: 0.0.2, which changes only the install text on the PyPI page -- and fixes __version__

WHY THIS VERSION EXISTS

PyPI freezes the project description into the uploaded metadata, so the page for 0.0.1 still says "not
on PyPI yet". Editing the README cannot change it; only a new upload can. That is the entire reason for
0.0.2, and the changelog says so plainly rather than dressing it up as improvements that do not exist.

A REAL DEFECT FOUND WHILE PREPARING IT

After installing 0.0.2 from its own sdist:

    pip show westata          -> 0.0.2
    westata.__version__       -> 0.0.1

`__init__.py` carried a hardcoded version string maintained separately from pyproject.toml. They drifted
within minutes of the first release, and nothing reported it: both values are plausible strings, and a
reader of `westata.__version__` had no way to know it was stale. Anything keying compatibility logic or
logs off it would have silently used the old number.

Now read from `importlib.metadata`, which is what pip writes and what `pip show` reports. A literal
remains only as a fallback for an uninstalled source tree, where no distribution metadata exists.

tests/test_version_consistency.py asserts `westata.__version__ == pyproject.toml version`, so the two
cannot drift again, plus a shape check so a malformed version is caught before PyPI rejects it.

The metadata check matters most: the whole point of this release is what that text says, so it was
inspected in the built artefact rather than assumed from the source file.
