fix(sqreg): use Stata RNG and sort-aware row pairing; gap still open at 3.9e-02

Retracts the round-5 claim (committed separately as a doc fix) that `qreg [fweight]` is not replication, and
rebuilds the bootstrap around what is now verified.

VERIFIED IN THIS ROUND, each against a live Stata:

    weight vectors, draws 1..4          element-for-element equal to Stata's `w` (n = 20, 40, 200)
    one weighted fit                    equal to `qreg [fweight=w]` to 3.5e-16
    `qreg_c` vs `qreg`, same weights    identical coefficients
    `wlsiter(1|3|8)`                    does not change the answer
    `qreg [fweight=w]` vs row expansion  IDENTICAL (this is what round 5 got wrong)

The round-5 error was pairing a SORTED weight column with an UNSORTED dependent variable: `bsampl_w` ends with
`sort r w`, so `w` read back afterwards belongs to the permuted dataset. Every number in that claim came from that
one misalignment. `[U] 20.24.1` states the principle the corrected measurement confirms.

The bootstrap now uses Stata's MT19937-64 rather than numpy's generator, consumes the uniforms in the block order
`bsampl_w.ado` uses (all targets, then all tie-breaks), and resolves retained rows through the sort permutation
rather than by interpreting the target value as an original row index.

STILL OPEN: the replicate variance is 0.0299 against Stata's 0.0490, ratio 1.64. That ratio is NOT
reps/(reps-1) = 1.01, so it is not a divisor; and the components above are each exact, so it is not the draws, the
weights or a single fit. Recorded rather than papered over.
