THE CORRECTION MATTERS MORE THAN THE FINDING. The same run reported `zip` at 0.75 relative, which I
first wrote up as a genuine defect -- and §8.12 existed precisely to stop the stopping-point
explanation being stretched over real bugs. The 0.75 was my own probe's fault:

    from_formula("y_zi ~ x1 + x2")                     <- 3 parameters, count equation only
    zip y_zi x1 x2, inflate(x1 x2)                     <- 6 parameters

Comparing a three-parameter model against a six-parameter one manufactured the defect. With
`inflate="x1 + x2"` supplied, the standard errors match Stata element for element and differ only in
ORDER -- westata puts the intercept first in each block, Stata puts it last. Aligned by name they agree.

That is the mirror image of the failure mode this project keeps hitting, and it is now stated as such
in the document: extending a legitimate explanation over a real defect, and recording a non-defect as
real, both come from the same root -- not confirming that both sides are computing the same thing.

`ztp` is left explicitly unresolved rather than folded into either category: the probe could not align
the evaluation point, so nothing is claimed about it.
