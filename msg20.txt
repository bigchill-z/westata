feat(packaging): make the wheel installable and runnable -- four real defects found by installing it

The question was "can this be pushed to PyPI". The answer was no, and the only way to find out was to build the
wheel and install it in a clean venv. `pip install` reported success every time, so nothing in the existing test
suite could have caught any of this.

1. THE PACKAGE IMPORTED NOWHERE. Four third-party imports were used and declared nowhere:

       pyfixest       module-level in estimators/hdfe.py      REQUIRED (reghdfe IS a layer over pyfixest)
       linearmodels   module-level in estimators/iv.py        REQUIRED (ivregress uses it as its backend)
       pyyaml         module-level in conformance/registry.py REQUIRED
       arch           deferred inside functions in tseries.py optional -- only ARCH/GARCH and the PP test

   So `pip install westata` succeeded and `import westata` raised ModuleNotFoundError. pyfixest, linearmodels and
   pyyaml are now dependencies; arch is an extra (`pip install westata[arch]`) because making a large optional
   dependency mandatory would penalise users who never run those two commands.

2. SUREG CRASHED ON A VALID SYSTEM. Found by the smoke test, then reproduced in the source tree:

       ws.Sureg.from_formula(["y ~ x1", "y ~ x2"], frame).fit()
       ValueError: param_names must be unique

   Two equations on the same dependent column were both labelled `y`, so each intercept became `y:_cons`. Stata
   avoids this by naming equations after the dependent variable and rejecting duplicates outright. Rejecting a
   valid model to mirror a restriction that exists for Stata's own naming system would be the wrong trade, so the
   SECOND equation is disambiguated (`y#2:...`) and the first keeps its plain label. The ordinary case
   (`price` / `mpg`) is untouched -- asserted explicitly, because a fix that renamed everything would otherwise
   pass.

3. THE OPTIONAL DEPENDENCY FAILED BADLY. Without `arch`, users got `ModuleNotFoundError: No module named 'arch'`
   from inside a call, with no hint that this was an extra rather than a broken install. Both imports now raise
   `UnsupportedError` naming the exact command to run.

4. NO LICENSE. `pyproject.toml` declared `license = { text = "Proprietary" }` and no LICENSE file existed. PyPI
   rejects neither, but it makes the package unambiguously undistributable. MIT LICENSE added, field changed to a
   file reference, and verified present in the built wheel as `dist-info/licenses/LICENSE`.

VERIFIED, not assumed -- each step run rather than reasoned about:

    python -m build                          built wheel + sdist
    twine check dist/*                       PASSED on both
    pip install <wheel> in a fresh venv      installs with dependencies resolved
    import westata                            ok
    OLS, QuantileRegression, Logit, FEOLS, IV2SLS, Sureg, Heckman, conformance   8/8 run
    arch absent                              UnsupportedError with the install hint

The name `westata` returns 404 on PyPI, so it is available.

Suite: 1434 passing (3 new tests for the sureg name collision).

Note on scope: this makes the package BUILD, INSTALL and RUN correctly. It does not make it release-ready in the
sense of versioning policy, a changelog, or CI -- and version 0.0.1 with Development Status 3-Alpha is honest
about that. The conformance evidence (52 E3 / 26 E2 / 9 E1) is a separate question from whether the artifact is
well formed, and this commit only addresses the latter.
