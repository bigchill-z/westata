# Writing the API reference — the contract every片 follows

This directory holds the machine-readable material for `docs/API.md` and
`docs/API.zh-CN.md`. Nothing in those two files is typed by hand except in the sense that
the prose in `prose_*.json` is hand-written; every signature, every example input and
every example OUTPUT is generated by `docs/collect_api_reference.py`, which executes the
examples against real data.

## Why it is built this way

A manual of 189 entries (126 exports + 63 result members) written by hand will drift from
the code. This repository has already paid for that lesson three times: README test counts
that lagged the suite, a Quick start that had never been run, and `e(aic)` presented as a
Stata macro when `regress` stores nothing of the sort. Generating the signatures and the
outputs makes those classes of error impossible for anything mechanical, and leaves only
the prose to get right — which is reviewable.

## Files

| file | owner | content |
|---|---|---|
| `api_data.json` | generated | signatures, docstrings, result surface |
| `prose_estimators_*.json` | one writer each | prose for estimator classes |
| `prose_postestimation.json` | one writer | prose for functions and result methods |
| `prose_core.json` | one writer | error types, helpers, `StataResults` |

## Entry format

Every entry is keyed by the exact export or member name. Required fields:

```json
{
  "StataName": {
    "stata": "the Stata command this corresponds to, or \"(no Stata equivalent)\"",
    "en": "one paragraph: what it does, what it returns, anything surprising",
    "zh": "the same paragraph in Chinese — a translation, not a different text",
    "example": "a runnable expression, or a short newline-separated script",
    "notes_en": "optional: a caveat worth warning about",
    "notes_zh": "optional, required when notes_en is present"
  }
}
```

## Rules for `example`

1. **It must run.** The collector executes it; a failing example is printed in the manual
   as an error, which is the worst possible outcome for a reader. Run
   `python docs/collect_api_reference.py --check` before handing the file back.
2. **It must produce something worth printing.** Prefer `.summary(style="stata")`, a
   `to_dict()`, or a small numeric value over a bare object repr.
3. Available in scope: `ws`, `np`, `pd`, and `base` — a 200-row frame with these columns:
   `y x1 x2 x3 yb ycnt ycens lo hi y1 y2 firm year ypanel treat ytreat sel yselect`.
4. Keep it short. One or two lines is the target; a three-line script is the maximum.
5. The **last line** is what gets shown as output, so end on the interesting call.
6. Do not import anything; `ws`, `np`, `pd` are already there.

## Rules for `stata`

State the command as the reader would type it, including the options that matter:

* `regress y x1 x2` — not `regress`
* `logit y x1, vce(robust)` when the option is the point
* `(no Stata equivalent)` for things Stata cannot do, and say why in the prose

## Rules for the prose

* English and Chinese must say the SAME thing. The Chinese is not a summary and not a
  re-interpretation; a reader of either must not learn a different fact.
* Say what is surprising. Three recurring surprises are worth a sentence each when they
  apply: a macro Stata does not store, a default that differs from Stata, and an
  implementation that refuses something.
* Do not claim a number matches Stata unless it was measured. "Matches Stata" without
  evidence is the failure this repository keeps correcting.
* `notes_en` / `notes_zh` are for caveats only. If there is nothing to warn about, omit
  them — an empty caveat teaches the reader to skip the field.

## Verification a writer must run

```bash
.venv/Scripts/python.exe docs/collect_api_reference.py --check
```

This prints, for the entries it was given, which examples failed to run and which exports
still have no prose. It must report zero failures before the file is handed back.
