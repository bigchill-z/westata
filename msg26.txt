docs: add GUIDE.md -- a full usage guide with same-data comparisons against Stata

Adds docs/GUIDE.md (581 lines, 136 tables), generated from measurement rather than written.

WHAT IT CONTAINS

  * what the library is, and what the E1/E2/E3 evidence grades mean
  * installation (corrected -- `westata` is not on PyPI, so the command installs from the repo)
  * the API shape, with runnable examples
  * a command-by-command map of 54 estimators organised by family: linear/IV, panel, discrete
    choice and counts, limited-dependent, quantile, systems, causal, time series, post-estimation
  * 21 side-by-side comparisons against live Stata, with every coefficient and standard error
    shown to 10 significant figures
  * known deviations, including the nine E1 commands with their measured worst case and the reason

THE NUMBERS ARE GENERATED, NOT TYPED

  docs/build_doc_data.py      builds three datasets: Stata's own auto.dta, a 200x8 panel with a
                              correlated effect, and a 600-row cross-section with endogeneity,
                              treatment assignment and selection. Seeds recorded.
  docs/collect_comparison.py  sends ONE array to both programs, takes full-precision e(b)/e(V) from
                              Stata, and writes docs/comparison.json
  docs/generate_guide.py      renders GUIDE.md from that JSON

  A number that is not in comparison.json cannot appear in a table. That constraint is the point:
  the README once contained a Quick start that had never been executed and quoted an F statistic
  nobody could have obtained from the code beside it. Generating the tables makes that class of error
  impossible for the numeric claims.

RESULT: 21 commands, 0 errors. 10 agree to machine precision (below 1e-12), 16 to better than 1e-9.
Worst case across all of them is 5.8e-05, on `xtpoisson, fe` standard errors.

FOUR THINGS MEASUREMENT TAUGHT, all now documented rather than smoothed over:

1. `logit vce(robust)` differs from our HC1 by 0.692%, and the arithmetic identifies it as a
   convention rather than a fault:

       sqrt( (n/(n-k)) / (n/(n-1)) ) = 1.0069204978
       observed ratio                 = 1.0069204993

   Stata divides by n-1 for likelihood commands; statsmodels-style HC1 divides by n-k. For `regress`
   Stata uses n/(n-k) and our HC1 matches exactly, so the divergence is specific to that family. The
   guide gives both numbers and says which is which -- reporting "0.69% disagreement" unexplained
   would read as a defect.

2. `tobit` reports the error scale on different scales: Stata stores var(e.rep78) = 0.807583, we
   expose /sigma = 0.898656, and 0.898656^2 = 0.807583. Compared directly, that looks like an 11%
   error; it is a units difference. Slopes match to 1e-15.

3. Seven commands report a different N, for four distinct reasons: sureg counts per equation vs
   stacked rows (74 vs 148); tobit drops 5 missing observations (74 vs 69); xtlogit/xtpoisson fe
   condition out non-varying entities and xtreg be collapses to group means; heckman has a full
   sample and a selected one. All four are now stated in the guide, because every one of those
   numbers looks like a bug on its own.

4. `xtreg, be`'s N is the number of GROUPS, not rows. That is worth saying explicitly -- 200 versus
   1600 invites the wrong conclusion.
